## 1. 一句话产品目标与目标用户

**产品目标**:校招快填是一个桌面悬浮球工具,参考用户个人简历,自动填写不同公司校招网申页面的简历内容——**只填不提交,提交永远由用户人工完成**。

**目标用户**:需要向多家公司投递校招网申的应届毕业生(含即将毕业的在校学生)。痛点:同一段个人信息在不同公司网申系统里反复手敲十几个字段,既慢又容易抄错。

## 2. 产品铁律(优先级最高)

- **只填不提交**:填写完成后,必须由用户人工核对并自行点击提交,工具永远不代为提交。
- 该铁律贯穿所有状态与迭代,任何后续功能(真实站点适配等)不得违反。

## 3. 主流程

```
双击启动工具(①)
   → 屏幕出现悬浮球(②)
   → 悬浮球引导用户进入校招网申页面(③)
   → 用户点击「开始填写」
   → 工具自动检测当前页面是否符合要求(④)
        ├─ 不符合 → 继续引导(回到③)
        └─ 符合 → 逐字段自动填写,输入框逐个高亮(⑤)
   → 填写完成,提示人工核对(⑥)
   → 用户自行核对并点击提交(工具不参与)(⑦)
```

Demo 轮的映射:①「双击启动」在未来为 Electron 桌面程序;本轮以打开 Demo 网页(开发服务器)代替。③ 的引导目标为 Demo 内置的模拟网申页 `#/apply`。④ 的「不符合 → 继续引导」分支在 Demo 中的定义与可达路径见 §4 补充规则(双阶段检测)。

## 4. 悬浮球状态机

悬浮球为全局组件:初始位于屏幕右下角,约 64px 半透明渐变圆球,标「填」字;支持 pointer events 拖拽,可拖至**浏览器视口内**任意位置(Demo 口径:悬浮球是页面内 fixed 元素,不要求、也无法拖出浏览器视口);点击(非拖拽)展开/收起面板。面板顶部始终显示当前简历名(如「当前简历:张三-前端开发方向」)。

| 状态 | 触发条件 | 面板文案 | 面板按钮 |
| --- | --- | --- | --- |
| 待机 | 当前不在网申页面(hash 非 `#/apply`,或未检测到表单容器;含复检未通过、检测/填写中/完成态离开 `#/apply` 等情形,见补充规则) | 两种变体——默认:「悬浮球已就绪,请进入校招网申页面」;复检失败进入时:「✗ 未检测到网申表单,请进入校招网申页面后再试」 | 「进入演示网申页」→ 跳转 `#/apply` |
| 就绪 | 在 `#/apply` 且 DOM 存在 `[data-campus-form]` | ✓ 已检测到网申表单(演示公司) | 「开始填写」 |
| 检测中 | 用户点击「开始填写」后,对当前页面重新检测,持续约 800ms;出口有二:通过→填写中,不通过→待机(见补充规则「双阶段检测」) | (spinner)正在检测当前页面… | 无 |
| 填写中 | 检测通过;按字段顺序逐个填入,约 200ms/个 | 正在填写 x/13:字段名 | 无 |
| 完成 | 13/13 字段全部填入 | ✓ 填写完成 13/13。请人工核对后自行提交,工具不会代为提交。 | 「清空重填」 |

补充规则:

- **双阶段检测**(对应核心诉求③④「点击后检测,不符合则继续引导」):
  - 阶段一·静默判定:路由或 DOM 变化时自动判定当前是否网申页,决定「待机 / 就绪」;
  - 阶段二·主动复检:用户点击「开始填写」后,在约 800ms 的「检测中」内**重新检测**当前页面。复检通过 → 「填写中」;复检不通过 → 回到「待机」继续引导,待机文案使用失败变体「✗ 未检测到网申表单,请进入校招网申页面后再试」(按钮不变)。**该 ✗ 文案为统一依据**:技术方案如写复用默认待机文案,以本文档为准并需同步修订。
  - Demo 中因「就绪」的前提即检测已通过,正常路径下复检恒通过;但「检测不通过 → 待机」是**必须实现的状态机边**(与诉求「不符合则继续引导」对齐,也是后续真实站点阶段点击后检测失败的落点),Demo 中可通过「在检测窗口内离开 `#/apply`」触发验证(见下条)。
- **路由切换打断**:在「检测中」「填写中」或「完成」态,用户离开 `#/apply`(点浏览器返回、直接改 hash 等)时,悬浮球回到「待机」并显示引导文案;表单内已填入的字段**保留不清空**(含完成态已填好的 13 项)。返回 `#/apply` 后重新满足就绪条件,回到「就绪」,面板按钮**仅有「开始填写」**(注:「清空重填」按钮只存在于完成态面板,就绪态不提供);再次「开始填写」将从第 1 个字段起**全量覆盖**重填,故打断恢复后无需单独清空。
- **填写中**:每填入一个字段,该输入框短暂高亮;面板计数从 1/13 递增到 13/13。
- **完成 → 清空重填**:点击「清空重填」清空表单,状态回到**「就绪」**(非「待机」:清空后用户仍在 `#/apply` 且 `[data-campus-form]` 容器仍存在,满足就绪触发条件)。**本条为状态机迁移的统一依据**:技术方案中的状态机图/映射表如与此不一致(如画成「完成 → 清空重填 → 待机」),以本文档为准并需同步修订技术方案。
- **检测逻辑(Demo 版)**:当前 hash 为 `#/apply` 且 DOM 存在 `[data-campus-form]` 即视为网申页面(阶段一与阶段二复检使用同一判定)。
- **数据来源**:填写数据 = 当前使用的 mock 简历;切换简历后需在表单页「清空重填」,字段值随简历变化(如求职意向从「前端开发工程师」变为「产品经理」)。

## 5. Demo 页面功能清单

路由共两个:`#/resume`(默认页)与 `#/apply`。打开 Demo 时无 hash、或访问未知 hash(如 `#/foo`)时,一律重定向到 `#/resume`。

### 5.1 页面一 `#/resume` 简历管理

- 展示两份 mock 简历:**张三-前端开发方向** / **张三-产品方向**。
- 卡片式字段预览,字段:姓名、性别、出生日期、手机、邮箱、政治面貌、籍贯、学校、专业、学历、毕业时间、求职意向、自我评价(共 13 项,与网申表单一一对应)。
- 点击卡片切换「当前使用」简历;当前使用的简历有醒目标记。

### 5.2 页面二 `#/apply` 模拟网申表单

- 页面标题:「演示公司 2027 届秋季校园招聘」。
- 表单容器带 `data-campus-form="demo"` 属性(供悬浮球检测)。
- 页面顶部提示条:「演示模式:表单为模拟页面,数据为模拟简历」。
- 13 个空字段:

| # | 字段 | 控件 | 取值/说明 |
| --- | --- | --- | --- |
| 1 | 姓名 | 文本 | — |
| 2 | 性别 | 单选 | 男 / 女 |
| 3 | 出生日期 | date | — |
| 4 | 手机 | 文本 | — |
| 5 | 邮箱 | 文本 | — |
| 6 | 政治面貌 | 下拉 | 群众 / 共青团员 / 中共党员 |
| 7 | 籍贯 | 文本 | — |
| 8 | 学校 | 文本 | — |
| 9 | 专业 | 文本 | — |
| 10 | 学历 | 下拉 | 本科 / 硕士 / 博士 |
| 11 | 毕业时间 | date | — |
| 12 | 求职意向 | 下拉 | 前端开发工程师 / 后端开发工程师 / 产品经理 / 算法工程师 |
| 13 | 自我评价 | textarea | — |

- 表单底部提供「提交申请(演示)」按钮:仅响应用户手动点击,点击后页面内提示「演示提交成功:未发送任何数据」;不发生任何真实网络提交。**按钮名「提交申请(演示)」与提示文案「演示提交成功:未发送任何数据」均为统一依据**,技术方案如用其他按钮名(如「提交申请」)或其他提示语,以本文档为准并需同步修订。该按钮是主流程第⑦步「用户自行核对并点击提交」在 Demo 中的正向落点——工具在任何状态下都不得触发它(铁律)。

### 5.3 悬浮球(全局组件)

- 见第 4 节状态机;在两个页面及路由切换过程中始终存在、行为一致。

## 6. MVP 边界

**本轮做**:

- Vite + React + TypeScript 项目搭建,hash 路由。
- `#/resume` 简历管理页(两份 mock 简历 + 切换当前使用)。
- `#/apply` 模拟网申表单页(13 字段 + 演示提示条 + `data-campus-form` 容器)。
- 悬浮球全局组件(拖拽、点击展开/收起、五态状态机、逐字段填写与高亮)。
- 【2026-10-03 追加·用户验收反馈推进】Electron 桌面级悬浮球(独立置顶透明窗口,可拖至屏幕任意位置)。
- 【2026-10-03 追加】主窗口内嵌网申浏览(WebContentsView + 地址栏/前进/后退/刷新);
  站点适配器框架(mokahr 专属 + 通用表单);注入式通用填写引擎(标签同义词匹配、
  下拉模糊匹配、单选组、原生事件写入,只填不提交);简历落盘 userData/resumes.json。

**本轮不做**(全部进入后续迭代清单):

- 真实公司网申站点的**深度**适配(专属字段选择器覆盖、登录态/验证码引导、iframe 跨域表单);
  本轮已交付适配器框架与通用标签匹配引擎,对多数标准表单可填,但未逐站点验证调优。
- 真实简历的导入与解析(PDF/Word 等)。
- 后端服务、账号体系、数据持久化。
- Electron 桌面打包(「双击启动」在 Demo 轮以打开网页代替)。

## 7. 后续迭代清单(方向性)

1. **真实站点适配**:针对各公司校招网申系统(如页面结构各异的 ATS)做字段识别与填写。
2. **简历导入解析**:导入 PDF/Word 简历,解析为结构化字段。
3. **Electron 打包**:交付双击即用的桌面程序,悬浮球常驻系统层面。
4. **多简历管理**:多份简历的增删改查、按投递方向快速切换。
5. **字段映射自定义**:用户自定义「简历字段 ↔ 网申字段」的映射规则。
6. **失败项标记**:填写失败/未匹配的字段在面板中标记,提示人工补填。
7. 其他(填写日志、快捷键、更多控件类型支持等)。
