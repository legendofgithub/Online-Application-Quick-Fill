# 校招快填 · Online Application Quick Fill

> 把简历存在本地,打开任意公司的校招网申页面,点一下,它替你把这个页面上几十个空一格一格填好。
> **产品铁律:只填不提交** —— 最后一步永远由你自己核对、自己点击提交,工具绝不代提交。

---

## 一、它解决什么问题

应届生秋招往往要投**几十到上百家**。每一家的网申系统都要你把**同一份信息再填一遍**:

教育背景、实习经历、项目经历、获奖、外语成绩、父母信息、户口、内推码、证明人……
字段名不一样、顺序不一样、下拉选项的写法也不一样。

于是每次都要经历:

- 手动填一家 **20~40 分钟**,几十家就是**几十个小时**的重复劳动;
- 日期要选下拉(`2025年9月` 还是 `2025-09` 还是拆成"年+月"两个框);
- 多段实习要先点一次「添加」才能多出一行,然后再填;
- 填错、漏填、格式对不上,提交后才发现。

**校招快填就是把这件事从"每次重填"变成"点一下"。**

---

## 二、它怎么工作

```
① 简历库(存在本机)         一次录好,长期复用
        ↓
② 在内置浏览器里打开网申页面  登录一次,之后长期保留登录态
        ↓
③ 点「开始检测」→「开始填写」  自动识别字段 → 逐格填写 → 镜头跟着走,看得见它在做什么
        ↓
④ 遇到多段经历自动点「添加」   没有的行它自己点出来,再填
        ↓
⑤ 停在这里,交给你             核对 → 你自己点提交
```

### 简历库支持的结构

| 类别 | 说明 |
| --- | --- |
| 基本信息 / 联系方式 / 网申附加 | 60+ 个单值字段(含户口、内推码、父母单位职务、是否接受远程面试等) |
| **教育背景(可多段)** | 学校 / 院系 / 专业 / 辅修专业 / 学历 / 学制 / 入学·毕业时间 / GPA / 专业排名 / 导师 / 实验室 / 研究方向 |
| **实习·工作经历(可多条)** | 公司 / 职位 / 性质(兼职·实习·正职) / 起止时间 / 描述 / 证明人 / 所在部门 / 汇报对象 |
| **项目经历(可多个)** | 项目名称 / 角色 / 起止时间 / 描述 / 链接 |
| **获奖荣誉(可多项)** | 获奖类型 / 奖项名称 / 获奖时间 / 级别 |
| 自定义字段 | 每家公司都会问的开放问题(如"常用的 AI 工具""与 AI 协作的项目") |

> 多条记录会**按行对齐**填写:你简历里的第 2 段实习 → 页面上的第 2 行,不会串行。

## 三、"优化自己的数据库" —— 它会越用越好用

这是这个工具和"一次性脚本"最大的区别:**每填一次,你的简历库就更全一点。**

每次填写完成后,可以导出**填写报告**(两个入口):

- **「导出报告」** —— 自己挑位置另存为 Markdown;
- **「导出到 DSH」** —— 直接写进固定收件箱,并把一句提示语放进剪贴板,交给 AI 助手分析改进。

报告会分成几类,清楚地告诉你"为什么这一格没填上":

| 报告小节 | 含义 | 你该做什么 |
| --- | --- | --- |
| 一、页面有、简历里没有的字段 | 这家公司问了,但你的简历里没这一项 | **补进简历** → 以后同类表单就能自动填 |
| 二、匹配到简历字段但没能填上 | 常见两类:① 你的简历里这项还是空的 ② 控件选项和值对不上 | ①补内容 ②属于工具要修的部分 |
| 四、未匹配控件的结构 | 控件的真实样子(标签/类型/是否只读/所属区块)+ **祖先链** | 工具据此定位 |
| 五、「添加」按钮诊断 | 需要新增几行、找到的按钮是什么 | 多段经历能否自动生成 |
| 六、自绘下拉填写失败的现场 | 下拉有没有打开、有几个候选、候选原文是什么 | 自绘下拉能否选对 |
| 七、匹配到但没填上的控件结构 | 控件结构 + 当时取到的值 | 定位"赋值被页面忽略"这类情况 |

**于是形成一个正向循环**:填一次 → 报告告诉你缺什么 → 补进简历 → 下次更多字段自动填上 → 需要手动处理的越来越少。

## 四、功能一览

### 填写引擎(通用站点适配,不写死某一家)

- **同义词匹配**:`毕业院校 / 学校名称 / 最高学历院校` 都能认成"学校";`工作业绩 / 主要职责 / 实习内容` 都能认成"经历描述"
- **区块识别**:从控件向上找出它属于教育 / 实习 / 项目 / 获奖 / 基本信息里的哪一块
- **行级对齐**:第 k 次出现的同名字段 → 第 k 条记录
- **起止时间配对**:一对"开始/结束"控件自动分开填,不会两半填成同一个值
- **日期候选写法**:`2025-09-01` 会依次尝试 `2025-09`、`2025/09`、`2025年9月`、`2025年`、`9月`、`09` —— 整日期下拉 / 年下拉 / 月下拉都能命中
- **多段值分段**:籍贯存成"某省;某市;某区"时,逐段作为候选尝试
- **自绘下拉**(非原生 `<select>` 的组件):识别触发器、点击、读选项、选中;失败时回退为直接赋值
- **自动点「添加」**:按记录条数把新行点出来(白名单 + 黑名单双重约束,**绝不会点到提交/删除**)
- **镜头跟随**:填写时画面跟着进度走,看得见它在工作
- **只填不提交**:不触碰任何提交 / 保存 / 删除类按钮

### 应用本身

- **悬浮球**:可拖拽,五态状态机(待机 / 就绪 / 检测中 / 填写中 / 完成)
- **内置浏览视图**:地址栏、前进后退,与主界面切换
- **登录态持久化**:网申站点登录一次即长期保留(独立持久分区 + 退出时落盘)
- **未填字段标黄**:简历编辑器里把还空着的字段高亮出来(只提示,不强制填写)
- **简历存档工具**:一键把简历库导出成可读、可原样恢复的存档文件(自带校验)


## 六、安全与隐私

- **只填不提交**:工具从不点击提交 / 保存 / 删除类按钮;「添加」按钮的点击有白名单 + 黑名单双重约束。
- **数据只在本机**:简历库位于 `%APPDATA%\校招快填\resumes.json`,不上传任何服务器。
- **登录态只在本机**:网申站点的 cookie / localStorage 保存在应用的持久分区里,不导出、不外传。
- **可随时存档**:内置存档工具把简历导出成单文件(自我描述 + 可原样恢复 + 写入后立即回读校验)。

> **本仓库已脱敏**:示例简历是**完全虚构**的占位数据,不含任何真实个人信息;
> 含简历画面的自动化截图不入库;提交历史中亦无个人信息。

## 七、已知限制(如实列出)

| 项 | 现状 |
| --- | --- |
| 部分站点的**三级联动选择器**(如籍贯的省 / 市 / 区) | 尚未支持逐级填写 |
| 部分站点的**日历式日期面板** | 需要按年 → 月 → 日逐级点击,尚未支持 |
| 少数自绘日期控件(`[年][月] - [年][月]` 分片) | 标签在很外层,区块判定还在完善 |
| 站点适配的**通用性** | 引擎走通用匹配,不针对某一家写死;但每次遇到新结构都靠"填写报告"定位后再补规则 |
| 平台 | 目前仅 Windows 桌面 |

这些都会在上面的"填写报告 → 补规则"循环里逐步收敛。

## 八、技术栈与结构

**Electron + React 19 + TypeScript + Vite**;主进程负责窗口与 IPC,渲染层负责界面,填写引擎以注入脚本的形式跑在浏览视图的页面里。

```
electron/
├─ main.cjs            # 主进程:窗口、悬浮球、浏览视图、IPC、填写报告导出
├─ fillScript.cjs      # 通用填写引擎(注入到页面执行:匹配、区块、行对齐、日期、自绘下拉、点添加)
├─ adapters.cjs        # 站点识别(演示表单 / 通用网申)
└─ preload*.cjs        # 受控 API 桥接
src/
├─ App.tsx             # 主界面与路由(#/resume、#/apply)
├─ components/         # 悬浮球、面板、填写报告横幅、简历编辑器
├─ autofill/           # 状态机、字段映射、填写编排
├─ mock/resumes.ts     # 字段模型与(脱敏的)示例简历
└─ store/              # 简历库与当前使用简历
scripts/               # 测试、E2E、部署与存档工具
test-forms/            # 复现真实网申结构的测试夹具
docs/                  # 产品设计与技术方案
```
